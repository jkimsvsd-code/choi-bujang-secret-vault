# 내 보안 Agent 시작 틀 0.2.11

이 보안 Agent는 회사 직원이 자기 로그인 상태, 업무 앱 접속 결과, 최근 접속 기록과 보안 경보를 보는 보안 앱입니다. 13단계부터 22단계까지 이 프로젝트 하나로 화면을 채워 가며 완성합니다. 처음이라면 docs/GETTING_STARTED_STUDENT.md부터 읽습니다. 무엇을 왜 만드는지와 단계별 순서가 그 문서에 있습니다.

이 시작 틀을 받은 것만으로 단계를 통과하지 않습니다. 단계마다 docs/STUDENT_PROMPTS.md의 안내를 수업용 AI에 붙여 넣어 student/extension.mjs를 고치고, 화면에서 확인하고, 커밋한 뒤 ALEPH에 제출합니다. 제출하면 서버가 그 커밋의 코드를 받아 AI가 단계 과제 기준으로 읽고 판정합니다. 코드를 실행해서 판정하지 않습니다.

## 케셰브 15단계 저장점 (2026-10-19)

- renderEvents에 최신순 목록, 세 필터와 건수, 근거·규칙·접속/세션/기기 상태 상세를 구현했습니다. 받은 배열을 변경하지 않으며 다시 불러오면 이전 상세가 초기화됩니다. 다른 학생 함수는 보존했습니다.
- 본인의 최근 40건과 저장된 XDR 경보가 대상이며 전체 직원 기록·실시간 탐지가 아닙니다. 범위 문구는 제공 화면이 담당합니다. unknown은 확인 불가로 표시하고 실제 조치 버튼은 만들지 않습니다.
- 직접 실행한 문법·모의 DOM 점검과 별도로, 사용자가 필터/건수·정렬·상세/unknown·키보드·재조회 초기화를 화면에서 확인했습니다. 빈 배열·실패·계약 불일치·문자 그대로 표시·앱 ID 누락·조치 버튼 미생성은 Console 모의 입력으로 확인했으며 원래 목록 복원도 보고했습니다.
- 실제 SDP 연결, 실제 서버 장애/계약 불일치 재현, 공식 판정·진도 반영은 미확인입니다. 제출·배포·유료 AI 요청·보안 조치는 실행하지 않았습니다.
- 이 폴더에서 예제는 npm run demo, 기본 실행은 npm start, 문법은 npm run check입니다. http://127.0.0.1:5189/ 의 학생 보안 기록에서 필터·상세·다시 불러오기를 확인합니다. 정상 목록은 건수와 행이 일치하고 denied는 접속 거부로 표시되어야 하며, 오류는 빈 목록과 구분되고 이전 결과가 남지 않아야 합니다.
- 루트 설정 step=12와 judgeIssuer는 기존 자료실용으로 유지합니다. 설정 대조 및 제외 파일은 루트 README의 15단계 저장점에 기록했습니다. 이번 bundle·attack-check·공식 제출은 미실행입니다.

## 이전 학생 구현 저장점 (2026-10-19)

- `renderIdentity`는 보존했습니다. `renderDecision`은 요청 상태와 네 판정·이유·시각을 표시하며, unknown과 요청 실패를 허용으로 표시하지 않습니다.
- `renderStatus`는 기기·세션·알림·연결 점검을 구분하고 지정한 진단 6개 항목만 복사합니다. 16단계 일부 구현이며 전체 완료는 아닙니다. 나머지 대기 함수는 그대로입니다.
- 문법 검사와 모의 DOM 검사는 통과했습니다. 로컬 화면의 연결 없음·실패·알림·진단 표시와 복사 버튼 활성화는 확인했습니다. 실제 클립보드 복사 및 실제 SDP 연결·계정 판정·접속 요청의 키보드 결과 갱신은 미확인입니다. 공식 심판 통과나 진도 기록이 아닙니다.
- 이 폴더에서 `npm start`로 실행하고 `npm run check`로 문법을 확인합니다. 기본 실행은 연결 없음입니다. 개인 SDP 설정은 담당자에게 확인하며 임의로 만들지 않습니다.

## 실행 방법

검수 환경은 Node.js 24.19.0이며 외부 npm 의존성이 없습니다. 이 폴더의 PowerShell에서 아래를 실행하고 PC 브라우저로 http://127.0.0.1:5189 를 엽니다. 자세한 켜기·끄기·다시 켜기는 docs/STUDENT_LAUNCH_GUIDE.md에 있습니다.

    powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1

npm start도 같은 서버를 켭니다. 기본 실행은 실제 회사 시스템(기존 엔진)에 연결되지 않은 상태입니다. npm run demo는 예제 자료로 화면을 보여 줄 뿐이며 실제 연결이나 성취가 아닙니다. npm run check는 student/extension.mjs의 문법만 확인합니다.

## 지킬 것

- 기존 1~3차 프로젝트와 학생 파일은 지우거나 덮어쓰지 않습니다. 새 폴더에서 시작하거나, 이미 하던 프로젝트를 이어 씁니다.
- AI 열쇠·비밀번호·토큰을 코드, 커밋, 캡처, 도움정보에 넣지 않습니다. 주소나 열쇠를 직접 입력하는 칸도 만들지 않습니다.
- .env.example에는 비밀 없는 설정만 있습니다.
