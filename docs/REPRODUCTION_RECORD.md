증거는 **원문 확인**, **AI가 실행한 명령**, **예제(demo)/모의 검사**, **학생 직접 화면 확인 진술**, **실제 시스템 연결 검증**으로 구분한다. 과거 README의 관찰은 해당 당시 기록이며 이번 재현 통과로 옮기지 않는다.

## 현재 원문과 안내 대조

수정 함수는 없다. 학생 입력은 [21단계 설명서의 계약 표](STUDENT_RUNBOOK.md#5-구현-함수제공-코드입력-계약)를 따른다. `createStudentView()`의 renderIdentity, renderDecision, renderEvents, renderStatus, renderVulnerabilities, renderAiConnection, renderExplanation, renderAction과 `createEngine(host)`를 유지한다. 접근 요청은 `{appId}`, 판정은 allow/deny/challenge/unknown이다. 조치 표시는 succeeded와 `observation.effectApplied === true`를 함께 요구하며 접수만으로 효과 확인을 표시하지 않는다.

확인할 상태는 예제/연결 없음/실제 연결, 자료별 실패·빈 목록·unknown, 허용·거부·추가 확인, 조치 준비·접수·효과 관측이다. 함수와 표시 구현의 존재만 확인했으며 이번 실제 화면 검증은 미확인이다.

차이와 제한:

- package의 Node 기준은 24.19.0이고 실행 도구는 22~24를 허용한다. 21단계 기록은 24.21.0이다. 이번 새 환경의 버전은 실행해서 다시 기록하며 정확한 기준 버전 검증과 혼동하지 않는다.
- 학생 앱에는 외부 dependencies와 별도 lock 파일이 없다. 예제 실행에 npm 설치는 필요하지 않다. 루트 자료실은 별도 package-lock.json을 사용하며 필요 시 `npm.cmd ci`로 복원한다. 루트에는 start 스크립트가 없다.
- 제공 시작 안내의 21·22단계 미확정 설명과 이번 공식 안내가 다르므로 이번 공식 안내를 따른다. 제공 파일은 보존한다.
- 실제 버튼은 「원천 결과만 재조회」다. 학생 문구의 「연동 시스템 결과만 재조회」와 다름을 기록하며 제공 버튼을 바꾸지 않는다.
- 실행 경로는 복제본 기준 상대경로를 사용한다. 기존 인증·설정 파일을 복사하지 않는다. `.env.example`은 견본이며 npm 실행이 자동으로 .env를 읽는다는 뜻이 아니다. 실제 연결은 공식 설정 화면과 제공 연결 계약에 따라 별도로 준비한다.

## 한 번에 하나씩 진행할 순서

확인 1의 AI 로컬 점검: 2026-10-26 20:06:15 +09:00에 git status/diff/log와 파일 존재 여부를 다시 확인했다. 브랜치 main과 기준 HEAD는 그대로이고, 추적 파일 삭제·스테이징 변경은 없었다. 이번 변경은 README.md와 새 REPRODUCTION_RECORD.md이며, 앞서 열거한 미추적 자료 경로와 21단계 문서·학생 코드·제공 화면·설정 파일이 존재한다. 미추적 자료는 사전 내용 해시가 없어 내용의 완전 동일성까지 증명한 것은 아니다. 학습 DB는 접속하거나 변경하지 않았다. 루트 public/app.js는 기준 커밋에도 없으며, 실제 제공 화면 on-client/public/app.js는 존재하고 변경되지 않았다. 이는 AI가 실행한 로컬 파일·Git 점검이며 학생 화면 확인 진술은 아니다. 아래 후속 절차는 아직 실행하지 않았다.

1. 원래 폴더에서 `git status --short`를 실행하고 탐색기에서 README, docs/STUDENT_RUNBOOK.md와 기존 자료 폴더를 확인한다. 정상은 기존 자료가 있고 이번 문서 변경만 추가된 상태다. 기존 파일의 예상하지 못한 삭제·덮어쓰기가 있으면 다음 단계로 진행하지 않는다.
2. 이번 문서 두 파일만 변경 검토·비밀값 검사 후 명시적으로 커밋한다. `git add .`로 다른 자료를 포함하지 않는다. `git rev-parse HEAD`로 실제 제출 후보 해시를 확인한다. 커밋 전에는 최종 해시를 만들어 적지 않는다.
3. 프로젝트 밖의 존재하지 않는 새 폴더를 정한다. 원격에 후보가 있으면 `git clone --no-checkout https://github.com/jkimsvsd-code/choi-bujang-secret-vault.git <새폴더>`를 사용한다. 원격에 없다면 `git clone --no-hardlinks --no-checkout <원래Git최상위폴더> <새폴더>`로 커밋된 원문만 복제할 수 있다. 꺾쇠 부분은 실제 확인한 경로로 바꾼다. 이번에는 경로 미확정이므로 복사 실행용 명령이 아니다.
4. 새 폴더에서 `git checkout --detach <실제40자리커밋>` 후 `git rev-parse HEAD`와 `git status --short`를 확인한다. 후보와 해시가 같고 추적 파일 변경이 없어야 한다. 불일치는 재현 대상 오류로 남긴다. 미추적 인증·설정·DB 자료가 자동 이관된 것으로 간주하지 않는다.
5. 새 폴더에서 node/npm/Git/PowerShell 버전을 확인하고 기록한다. Node가 없으면 21단계 설명서의 기준 설치 후 새 PowerShell에서 다시 확인한다. 학생 앱 예제에는 의존성 설치 불필요, 루트 자료실 설치는 별도 필요 시에만 한다. 설치 생략과 설치 성공을 구분한다.
6. 새 폴더 Git 최상위에서 `powershell -NoProfile -ExecutionPolicy Bypass -File .\on-client\tools\start-alekov.ps1 -Demo -Port 5190`를 실행한다. 포트 충돌이면 기존 프로세스를 종료하지 말고 오류를 기록한다. 정상 시작 문구는 HTTP 응답 확인이며 AI 연결 성공이 아니다.
7. 브라우저에서 `http://127.0.0.1:5190/` → 「보호 현황」을 확인한다. 그 뒤 「업무 앱」의 「학습 자료실 접속 요청」은 allow, 「개발 저장소 접속 요청」은 deny, 「확인할 업무 앱 접속 요청」은 challenge가 기대값이다. 예제 판정이며 실제 접속 허용·차단 결과가 아니다. 「보안 기록」 event-01의 미지원 조치와 「다시 불러오기」 후 상세 초기화를 따로 확인한다.
8. 이번 실행 창에서만 Ctrl+C로 종료하고 새 HTTP 요청이 응답하지 않는지 확인한다. 같은 폴더에서 같은 명령으로 재실행하고 같은 화면을 다시 확인한다. 종료와 재실행 결과·시각을 각각 남긴다.
9. 미완료 실제 집행·연결 항목이 남아 있으면 검증 중으로 유지한다. 학생 확인은 학생 진술로 표시하며 서버 실행 검증으로 표현하지 않는다.

## 데이터 보존·백업·복원 계획

- Git clone은 커밋된 코드·문서·설정 견본의 복제다. 미추적 원고·워크벤치·로그·개인 설정이나 외부 DB를 백업하지 않는다. 원래 폴더를 그대로 보존하며 새 폴더 시험으로 대체하거나 삭제하지 않는다.
- 학생 데이터와 학습 DB의 별도 백업은 미실행이다. 실제 작업 전 데이터 소유자가 승인된 DB 백업 수단으로 프로젝트 밖 비공개 보관소에 보존하고, 백업 시각·범위·복원 가능 여부를 값 노출 없이 기록한다. 비밀은 공식 비밀 입력 화면에서 새 환경에 직접 설정한다.
- [정책 백업 설명](POLICY_BACKUP.md)의 사본은 판정 코드·허용 경로·SQL 원문이다. 실제 DB 정책 조회 백업이나 자료 전체 백업이 아니다. 사본 SQL을 운영 DB에 통째로 실행하지 않는다.
- 기존 지정 가상 메모 복원은 제한된 한 건의 복원이며 전체 DB 복구가 아니다. 실제 복원은 별도 승인·범위 확인 후 격리 환경에서 ID·소유자·해시·다른 자료 보존을 대조한다. 이번에는 백업·복원과 DB 쓰기를 실행하지 않았다.
- 기존 개인 설정·키 보관소를 새 폴더에 무작정 복사하지 않는다. artifacts, bundle-notes.json, artifacts/submission.json과 비밀·개인정보·메모 본문은 이번 커밋·제출 증거에서 제외한다.

## 최종 버전 고정과 제출 기록

문서·코드는 함께 커밋하고 실제 해시를 과제 화면과 재현 증거에 기록한다. 커밋은 자기 자신의 해시를 본문에 포함할 수 없으므로, 커밋 안 문서는 그 문서가 포함된 커밋을 버전 식별 기준으로 삼고 실행 후의 해시는 외부 실행 증거와 접수 화면에서도 확인한다. 기록 갱신으로 새 커밋이 생기면 후보가 바뀐 것이므로 새 최종 커밋을 별도 폴더에서 다시 확인한다. 코드 수정이 필요하면 이전 결과를 유지하되 이전 커밋 결과로 분리한다. 새 최종 커밋에서 확인하지 않은 항목은 미확인으로 남긴다.

22단계는 과제 화면에 저장소 URL과 실제 40자리 커밋을 직접 입력한다. 「포털 제출 준비」는 13~20단계 지원이므로 사용하지 않는다. 비공개 저장소를 공개로 전환하지 않는다. 같은 단계 「비공개 저장소 원문 준비 방법」 → 「원문 전달 도구 받기」의 도구 ZIP과 JSON 출력 폴더는 프로젝트 밖에 둔다. 실제 도구 경로·출력 경로·최종 커밋과 화면 명령을 확인한 뒤 Git 최상위에서 안내된 student-source-cli.mjs 명령을 실행한다. 아직 도구 경로와 화면 명령을 확인하지 않았으므로 임의 명령을 만들지 않는다.

도구는 커밋된 원문만 묶고 학생 코드를 실행하거나 업로드하지 않는다. 생성 JSON은 「비공개 저장소 원문 묶음」에서 선택한다. 학생이 저장소·커밋·단계를 확인해 제출하고 서버 상태·판정 설명을 확인한다. 원문 전달 실패만 있으면 기존 접수를 유지하고 「원문만 다시 보내기」를 사용한다. 원문 전달 완료와 AI 검토 통과는 별개다.

현재 커밋 생성·push·원문 묶음·단계 제출·AI 판정은 미실행이다.
